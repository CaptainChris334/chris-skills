# 代理客户端与基础排障

## 先讲清楚三个概念

- **客户端**：安装在设备上，负责读取配置并建立代理连接。
- **节点/出口**：代理服务器的地址、端口和协议参数；客户端本身不是节点。
- **订阅/配置**：一组节点参数的导入方式。它不是密码保险箱，不能在公开群里传播。

不要用“最好用”做比较。按设备、协议兼容性、是否需要规则分流、来源是否可信、更新维护情况来选。只建议从系统官方商店、软件作者或服务商的官方渠道获取客户端；不提供破解包和未知下载站。

## 新手安装与导入的通用流程

1. 先确认设备系统和客户端名称，不要让用户凭截图猜软件。
2. 从可信渠道安装，核对开发者名称和应用权限。
3. 只在用户自己的设备上导入合法购买的配置。
4. 先选一个节点，开启连接；系统弹出 VPN 权限时，由用户本人确认。
5. 先用普通网页测试，再测试 TikTok。
6. 记录客户端名称、模式、节点、测试时间；一次只改一个变量。

不要在聊天中要求完整订阅链接。让用户只提供：客户端名称、版本、模式、节点标签的打码截图。

## 通用故障树

### A. 客户端不能连接

依次检查：设备日期时间自动同步、网络本身可用、VPN 权限是否允许、配置是否过期、节点是否已失效、是否被其他 VPN/安全软件接管。每次只改一项。

### B. 已连接但网页打不开

优先判断 DNS、系统代理冲突、规则模式误配和 MTU/网络限制。先切换到客户端提供的另一种 DNS 或临时全局模式做对照；若全局能开、规则不能开，问题多半在规则而非节点。

### C. 网页能开但 TikTok 不正常

停止继续换节点。收集 TikTok 原文提示、账号状态、设备权限、应用缓存/版本和出口 IP 检测。不要把平台限制诊断成“再买一个 IP”。

## 每次输出

给出“现象 → 最可能原因 → 一个动作 → 预期结果 → 下一步”的五段式答案，并提醒用户不要发送密码、验证码、私钥和完整配置。
