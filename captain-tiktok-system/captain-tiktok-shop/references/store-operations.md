# 订单、客服、售后与持续运营

核对日期：2026-09-17。用于商品开始出单后的日常运营、异常处理、复盘和放大。发货、取消、退货、退款、客服和绩效时限按目标市场当前政策执行，不跨市场套用固定天数。

## 每日优先级

1. 处理违规、冻结、商品下架和平台待办；
2. 处理待发货、物流异常、缺货和可能超时订单；
3. 处理退款、退货、差评和客服消息；
4. 检查库存、价格、优惠和商品状态；
5. 推进内容、达人、广告和直播；
6. 复盘数据，确定第二天动作。

先保护店铺健康和真实利润，再追 GMV。

## 订单与发货

- 每天检查待处理、待发货、运输中、异常和取消订单；
- 按后台要求在时限内打印面单、交接并取得有效物流扫描；
- 发货前核对 SKU、数量、质量、配件、包装和面单；
- 缺货时立即停止对应库存和推广，按平台流程处理订单；
- 不上传虚假单号，不提前点发货，不用空包或错误物流制造履约；
- 记录延迟、丢件、破损和错误发货原因，向仓库追责并修流程。

多仓运营要核对库存同步、订单路由和退货地址。可售天数低于补货周期时，及时降推广或补货。

## 客服

按“确认问题 → 给明确方案 → 按时完成 → 留下记录”处理。优先回答尺寸、适配、使用方法、物流、缺件和退换货。

- 使用买家语言，短句回复；
- 不承诺无法控制的到货时间或结果；
- 不要求买家撤销合理投诉、修改真实评价或转到站外解决；
- 不索取不必要的身份证、支付信息和验证码；
- 同类问题重复出现时，改商品卡、包装说明或质检。

## 取消、退货和退款

先读取订单所在市场的当前页面和倒计时：

1. 确认请求类型、原因、证据和处理时限；
2. 对照商品描述、物流轨迹、质检和开箱资料；
3. 在后台允许的操作内接受、拒绝、退款或申诉；
4. 需要退货时使用平台认可地址和流程；
5. 处理后记录根因和损失；
6. 同一原因多次出现时暂停推广，修产品、页面或履约。

不把其他国家的退货天数写成统一规则。自动同意、退款不退货、争议和举证规则按当前订单页面执行。

## 评价与店铺健康

每日查看商品违规和知识产权通知、延迟发货、商家取消、物流异常、退款退货、差评、客服工单、质量问题和店铺权益限制。

收到违规时先保存原文、商品、订单和截止时间，再按证据整改或申诉。不删除问题后原样重上，不通过换词、换图或换类目规避审核。

## 数据复盘

### 每日看异常

检查流量、点击、加购、成交、广告花费、退款、待发货、缺货和违规。当天只处理明显异常和紧急履约，不因一小时波动反复改策略。

### 每周看漏斗与利润

按商品、内容、达人、广告和直播拆分：曝光、观看、商品点击、加购、成交、客单、采购、物流、平台费用、达人佣金、优惠、广告、取消、退款、差评、净收入、贡献利润、库存周转和断货风险。

用净利润和可持续履约判断，不用 GMV 代替利润。

### 每月做商品分层

- 放大：有利润、低售后、素材和供应可复制；
- 优化：有需求，但商品卡、价格、内容或履约存在一个明确短板；
- 观察：数据不足，继续小规模测试；
- 淘汰：持续负利润、高退款、高违规或供应不稳定。

每个商品只确定一个主要动作：加预算、补素材、改页面、改价格、补货、降库存或下架。不要同时大改所有变量。

## 持续增长循环

1. 从客服、评价、搜索词和评论提取新需求；
2. 优化商品卡、包装、说明和产品；
3. 把有效素材角度扩成自营内容和达人 brief；
4. 复投能带来净利润的达人和素材；
5. 用 GMV Max 和直播逐步放大；
6. 增加套装、规格、关联商品和复购；
7. 根据利润和库存决定扩品、扩仓或扩市场；
8. 重新进入“选品 → 上线 → 冷启动 → 放大 → 履约 → 复盘”循环。

扩国家前重新核对当地准入、税务、商品合规、物流、退货、结算和语言，不复制原市场设置直接开卖。

## 故障短版

> 目前判断：
> 影响订单：
> 截止时间：
> 现在只做：
> 完成标准：
> 如果失败：

规则说明仍使用 3–4 条短句；只有真实订单异常才使用这套字段。
