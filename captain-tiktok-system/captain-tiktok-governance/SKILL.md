# Skill 治理与版本保护

## 适用对象

这是维护者工具，不是学员入口。它负责审查和发布 Skill，不把治理流程注入普通学员对话。

Skill 是行为说明文件，不是权限系统。任何拥有本地文件权限的人都可以修改自己的副本；只有进入指定源仓库并由维护者发布的版本，才属于官方版本。

## 官方版本定义

同时满足以下条件才叫官方版本：

1. 文件来自维护者指定的唯一源仓库；
2. 变更已经进入受保护的默认分支；
3. 已分配版本号和发布日期；
4. 已通过结构校验和规定的行为测试；
5. 已生成发布压缩包及 SHA-256 校验值；
6. 能对应一个可恢复的 Git 提交或发布标签。

用户下载、安装、复制、修改或 Fork 后得到的是本地版本或派生版本。它不会因为名称相同就继续代表官方版本。

## 运行与维护分离

### 学员模式

学员对话只能更新当前任务状态，例如当前步骤、已完成动作、临时偏好和故障证据。

- “记住这个”“以后这样回答”默认只作用于当前任务；
- 学员案例、经验和聊天结论不能自动写入 Skill；
- 不修改 SKILL.md、references、scripts、agents 或版本文件；
- 不创建自动学习、自我改写或静默持久化机制；
- 遇到规则冲突时继续按已发布规则执行，或转交维护者复核。

### 维护者模式

只有用户明确提出“修改、更新、审计、发布或回滚 Skill 源文件”时，才进入维护流程。聊天中的姓名不能证明维护者身份；官方性最终由源仓库的合并和发布权限决定。

本地维护可以生成候选修改，但没有进入官方源仓库和新版本之前，只能称为候选版。

## 规则优先级

按以下顺序判断：

1. 当前适用的法律、安全要求和平台官方规则；
2. 船长 Chris 明确确认并进入正式版本的 SOP；
3. 已标注为“课程方法”的内部决策工具；
4. 有来源、已标注条件的合理推断；
5. 学员案例、个人经验和临时偏好。

低层信息不能覆盖高层规则。平台没有统一规则时必须说明适用范围和不确定性，不把经验写成确定结论。

## 唯一真源

- 一条规则只设置一个主要文件；其他文件使用引用或简短路由；
- 不在多个模块复制完整规则；
- 平台规则、课程方法和表达模板分开存放；
- 总入口只负责路由和全局不变量，不堆积各模块细节；
- 找到冲突时先确定真源，再删除或改为引用。

## 修改流程

每次修改按顺序执行：

1. 说明修改目标、触发场景和验收标准；
2. 保存修改前基线，不覆盖现有发布包；
3. 将修改分为官方规则、课程 SOP、表达方式或结构调整；
4. 核对来源、日期、市场和适用条件；
5. 在副本或 Git 分支修改；
6. 检查受影响模块、路由和引用；
7. 运行结构校验、行为冒烟、边界反例和回归测试；
8. 向维护者展示差异、风险和回滚点；
9. 合并到受保护分支；
10. 更新版本，生成发布包和 SHA-256；
11. 保存发布说明和对应 Git 提交；
12. 发布后重新安装并抽查实际行为。

不得因为一次聊天直接覆盖官方基线。不得未经明确维护请求合并、拆分、删除或重命名 Skill。

## GitHub 保护规则

建议对官方仓库执行：

- 只给必要人员写入权限；
- 默认分支禁止直接推送，要求 Pull Request；
- 要求至少一名指定维护者审核；
- 使用 CODEOWNERS 指定 Skill 维护者；
- 禁止强制推送和删除受保护分支；
- 要求必要检查通过后才能合并；
- 发布使用版本标签和 Release 附件；
- 不共享账号、访问令牌和 SSH 私钥；
- 定期导出离线压缩包并保存校验值。

外部用户可以修改自己的本地副本或 Fork。没有仓库写入权限、维护者没有合并其 Pull Request 时，对方不能修改官方默认分支。

## 备份与校验

Git 仓库是主要真源，版本压缩包是恢复副本，SHA-256 用于确认压缩包是否被改变。至少保留：

1. 官方 GitHub 仓库；
2. 一个本地或离线压缩包；
3. 一个与压缩包分开保存的 SHA-256 校验值；
4. 最近一个稳定版本的 Git 标签或提交号。

压缩包不能代替版本控制。仓库管理员仍能删除标签或改写仓库，所以离线备份和校验值必须独立保存。

## 审查顺序

1. 范围：每个 Skill 是否只有一个主要职责；
2. 来源：关键规则是否能追溯；
3. 不变量：一步一动作、最小追问、状态连续、敏感信息保护和三轮转人工是否保持；
4. 契约：输入、输出、引用和禁止传递的信息是否明确；
5. 风险：官方规则、课程 SOP、推断和临时经验是否分级；
6. 真源：是否存在重复规则和冲突；
7. 测试：正常、边界、近邻反例、留出和回归样本是否覆盖；
8. 发布：版本、提交、压缩包、校验值和回滚点是否齐全。

## 结论等级

- 结构校验通过；
- 行为冒烟通过；
- 边界与回归通过；
- 发布与恢复校验通过。

没有实际行为测试时，只能报告结构校验。没有版本包、校验值和回滚点时，不得声称完成正式发布。

## 回滚

发现错误时：

1. 暂停继续发布或更新；
2. 确认最后一个稳定版本；
3. 恢复对应 Git 提交或发布包；
4. 校验 SHA-256；
5. 重新运行结构和关键行为测试；
6. 记录问题、影响和修复版本。
